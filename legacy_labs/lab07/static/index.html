RELATIONSHIP DECISIONS

What is embedded and what is referenced?

EMBEDDED

Report → tags and classification

Small, bounded values are read with their report and rarely need independent updates. Embedding avoids extra reads.

REFERENCED

Report → source

sourceId points to a source shared by many reports. Source metadata changes independently; embedding it everywhere causes duplication and fan-out updates.

Embedded alternative: copy {name, trustTier, url} into each report. Report cards can then render in one read, but updates can leave stale copies.

REFERENCED

Report → indicators

indicatorIds refer to reusable IOC documents. The relationship can be many-to-many; indicators have their own confidence, type, and lifecycle.

Embedded alternative: store each indicator's type, value, and confidence inside the report. That speeds report-with-IOCs reads, but duplicates shared IOCs and complicates corrections and global IOC search.

↳
Try it yourself · Embed the source marking an actual threat

For a report classified as an actual threat, embed a source snapshot and the analyst's threat assessment in that report. A report-detail query becomes one document read, without a source lookup. Global source edits, correcting the assessment across reports, and cross-report source comparisons become harder; retain sourceId if normalized source management is still needed.

INTERPRETING SERVERSTATUS

Cache hit ratio

The script estimates interval hits as 1 − Δ(pages read into cache) / Δ(pages requested from the cache). It also reports cache bytes in use, configured maximum, pages loaded, and application-thread evictions.

A high hit ratio with few evictions suggests the sampled working set is warm. A rising read-in rate and evictions can indicate cache pressure. This estimate is workload- and interval-dependent; it is not a universal WiredTiger metric.
